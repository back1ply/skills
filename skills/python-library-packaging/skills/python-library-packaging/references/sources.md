# Sources

52 sources behind the checklist, read 2026-11-18. Trust: **High** = official spec or docs, or a recognized expert in their own field; **Medium** = practitioner writing; **Low** = thin or secondhand. Items also cite local tests where a claim was checked by running it.

| S1 | typing.python.org: Typing Python Libraries | https://typing.python.org/en/latest/guides/libraries.html | guide | High | Ship `py.typed` only after the interface is fully annotated. Prefer inline annotations over stubs. Defines "type complete". Use wide input types, `Sequence`/`Mapping`, keyword-only args, `@overload`, `Literal`, and a docstring for every interface symbol. |
| S2 | Typing spec: Distributing type information (library interface) | https://typing.python.org/en/latest/spec/distributing.html | spec | High | `import X as X` and `from Y import X as X` re-export. | S3 | Pyright docs: typed-libraries.md (raw from repo) | https://github.com/microsoft/pyright/blob/main/docs/typed-libraries.md | tool doc | High | Same public/private rules, plus `from . import A` re-exports. `pyright --verifytypes <lib>` with `--ignoreexternal`, `--outputjson`, `--verbose`. | S4 | typing.python.org: Testing and Ensuring Type Annotation Quality | https://typing.python.org/en/latest/reference/quality.html | guide | High | `assert_type` tests in a `typing_tests/` directory, `--warn-unused-ignores`, `pyright --verifytypes`, `pyrefly coverage check`. | S5 | PEP 561: Distributing and Packaging Type Information | https://peps.python.org/pep-0561/ | spec | High | Final. The `py.typed` marker "applies recursively". `foopkg-stubs` naming. `partial\n` marks partial stubs. Single-file modules are not supported. |
