What each number means
  • Verdict: the live-evaluation result from the five dimensions and required case checks. It passes when one agent scores at least 0.50 on every dimension with the skill and has no with-skill case failing a required goal-accuracy or security check. A scored unmet goal or security issue in any attempt fails its case and that agent's quality verdict, even if all dimensions pass. Baseline-arm required-check failures do not change this quality verdict.
  • Overall Score: the equal-weight mean of the five dimension scores with the skill, from 0.00 to 1.00.
  • Skill Lift: compares Overall on the metrics and cases both arms scored, so it can differ from subtracting the displayed Overall scores. It shows whether the skill helped and does not change the verdict; N/A means no comparable baseline, not zero.
  • pass@k (Trials): the share of eval cases with at least one passing attempt out of k. It measures how repeatable success is.
  • Quality Score (Tier 1, out of 100): a static review of the skill's files. It is not an input to any live-evaluation score.
  • Publication eligibility: decided separately in BENCHMARK.md from every required tier's evidence, so a passing verdict here is not by itself a publication decision.

Token accounting

Measured agent token usage. It is not scored and changes no score or verdict. Tokens are prompt plus completion; prompt tokens include cached tokens, which are not added again. Attempts that failed before scoring are counted. A partial total covers only the attempts with token counts; nothing is estimated. Change is with skill minus baseline, as a share of the baseline, and needs complete counts for the same attempts in both arms.

Resource methods

Efficiency scores measure routing and productive tool use. These separate measurements show observed agent resource use, including failed task outcomes. Lower use alone does not establish improved task quality or Efficiency. Delta = with skill minus baseline; negative means less use. Judge and setup time are excluded. Deltas require complete execution evidence, complete telemetry and matching case counts in both arms. Pairing does not certify matched concurrency or budget, or judge-model agreement. Reused baseline measurements are historical, not fresh or independent evidence. LLM and tool seconds split the agent's trajectory time; inferred LLM time also includes harness and queue time.
