# Disputed points

Where sources disagree. The SKILL.md defaults follow the last column. Item IDs point to [checklist.md](checklist.md).

| # | Debate | Side A | Side B | Recommended default and why |
|---|---|---|---|---|
| 1 | JSON by default when piped | **Auto:** default to JSON when stdout is not a TTY [S43, S47]. JSON-only output with `--human` [S46, py:S58]. | **Explicit `--json`:** TTY decides color and animation, not format [py:S16, S35 (gh plain unless `--json`)]. | Explicit `--json` (py dispute 7). New evidence: Codex can run commands in a PTY [S30], so "not a TTY" is not "an agent". Auto-switching would hand an agent a table in PTY mode and a human a JSON blob in `\| less`. |
| 2 | `--help` as JSON | `--help` emits JSON with commands, rules, and skills [S46]. | Human help stays text; machine listing is a separate command or spec [S40, S47 (progressive, no eager schema dumps)]. | Text help plus an optional `commands --json` or Usage spec (DISC-03). Agents read text help well [S27, py:S19]. |
| 3 | Exit 2 meaning | 2 = usage error (argparse, clap, Go `flag`, bash builtins; py patterns.md). | Arcjet uses 2 = auth error and 3 = validation [S43]. oclif uses 2 for every `this.error` [S19]. commander and yargs use 1 for usage [S17, E10, E11]. | 2 = usage only (EXIT-02). The parser ecosystem is split, so this needs code in Go and Node (patterns.md). Document the table whatever you choose. |
| 4 | Fuzzy "did you mean" suggestions | Suggest, never auto-run [py:S16, S1, S6]. | Arcjet disabled suggestions so unknown input fails outright [S43]. | Keep suggestions in the error text with exit 2. They help agents self-correct and are never executed. |
| 5 | NDJSON for large results | "Stream large result sets as NDJSON" [S48, py:S37]. | JSONL cost 2.6x with worse results in a measured agent test [S34]. | One document plus `--limit`/paging by default. NDJSON only for event streams (AGT-04). |
| 6 | No-args behaviour | Help on stdout, exit 0 (cobra's non-runnable root, E2/E3; py CLI-03 says only "no action"). | Usage on stderr, exit 2: no command was given, so it is a usage error (clap `arg_required_else_help`, E8). | Either, documented. Prefer exit 0 with help on stdout for multi-command tools: harnesses show a non-zero exit as a failure [S25], and running `tool` bare is a common discovery step. |
| 7 | Confirmation for destructive actions | Type the resource name to confirm (TTY) [S48]. Interactive confirmation plus `--force` without a TTY [S49]. | Structured `confirmation_required` result with exit 4 and the exact re-run command, so the agent asks the user [S43]. | `--yes` required without a TTY (AGT-07). The Arcjet envelope is a good extra for agent-heavy tools (AGT-10). Never auto-confirm from an env var (AGT-15). |
| 8 | Detecting agents through env vars | Cursor recommends `CURSOR_AGENT` checks for shell prompts [S31]. Claude Code documents `CLAUDECODE` "to detect when a script is running inside" it [S26]. | Names differ per vendor, Codex's `CODEX_CI` is undocumented [S30], IDE terminals set `CLAUDECODE` for humans too [S26], and the variables are unauthenticated [py:S38]. | Cosmetics only (AGT-15). Explicit flags remain the contract. |
| 9 | Skill vs MCP vs llms.txt for discovery | Ship a skill (Arcjet `skills` command [S43]; anc P8 [S41]). | A skill "only reaches developers who install it"; naming the CLI in docs agents already read had the bigger effect [S34]. MCP when there is no CLI [S27]. | Docs first (DISC-06), then an optional skill. MCP only for DISC-07 cases. llms.txt only on the docs site. |
| 10 | Pinning an exact exit code in Go script tests | testscript is the idiomatic Go CLI test tool [S22]. | Its docs only describe `exec` succeeding or failing [S22]. | testscript for flows and golden output. `os/exec` table tests for exact codes (TST-01). |
