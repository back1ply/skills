## Reference CLI tests (P1), 2026-11-18, Windows 10

The Go (cobra 1.10.2, x/term 0.48.0, go1.27.4), Rust (clap 4.6.8, Rust 1.99), and Node (commander 15.1.0, Node 24.22.3) reference CLIs in patterns.md were run through `scripts/cli_contract.py` with `PYTHONUTF8=0`: 15/15 checks each (help and usage errors on root and both subcommands, version, no hang with stdin closed, no ANSI, no stack trace on a missing file, valid `--json`, quiet exit after the reader closes the pipe at 200,000 lines). Unknown subcommand, extra positional, bad value, and missing argument all exit 2 with empty stdout and 1–7 stderr lines; a bare call prints help on stdout with exit 0. `--json` output is identical under `CLAUDECODE=1 CODEX_CI=1 NO_COLOR=1 TERM=dumb PAGER=cat CI=true` with stdin closed. commander's `parseAsync()` with `exitOverride()` (untested in E10) maps help to 0, usage to 2, and handler errors to 1.

Negative controls, built from the framework defaults, fail as expected: commander without `exitOverride` and the EPIPE handler exits 1 on usage errors and crashes on a closed pipe (exit 1, stack on stderr); the cobra template (`os.Exit(1)`, writes straight to stdout) exits 1 on usage errors and on a closed pipe; Rust with `println!` panics on a closed pipe (exit 101). gofmt, go vet, rustfmt, and clippy are clean. POSIX behaviour (SIGPIPE, Node pipe truncation) is still unobserved.
