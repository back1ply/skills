# Agent-friendly CLI checklist

70 items with stable IDs, language-neutral, with per-framework notes in the Verify column. Sources: [sources.md](sources.md) (`S` = source, `E` = research experiment, `P1` = the reference CLIs in patterns.md, `py:` = a source of the `python-cli-packaging` skill; `from py X` = item X of that skill, generalized). Commands in tables escape `|` as `\|`.

**Shared with python-cli-packaging:** 44 rows here are the source for that skill's matching rows (rule text and severity). After editing one, run `just sync` from the skills repo root; CI fails if the two drift.

Modes: **B** build, **C** convert, **A** audit. `tool` is the CLI under test.

### 2.2 Output streams (OUT)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|
| OUT-01 | Data goes to stdout. Logs, progress, warnings, errors, and prompts go to stderr. | MUST | B C A | `tool cmd 2>/dev/null` shows only data and `tool cmd >/dev/null` only diagnostics. Grep for `fmt.Println`/`println!`/`console.log` used for diagnostics. oclif: use `this.logToStderr`, and note that `console.log` is not suppressed under `--json` [S19]. | from py OUT-01; S28 (Codex exec as exemplar) |
| OUT-02 | No ANSI escapes when stdout is not a TTY, when `NO_COLOR` is non-empty, when `TERM=dumb`, or with `--no-color`. Decide with an isatty check plus `NO_COLOR`, never with `TERM` alone: Claude Code runs commands with `TERM=xterm-256color` and no TTY (E13). | MUST | B C A | `tool cmd \| grep -c $'\x1b\['` → 0. `NO_COLOR=1 script -qc "tool cmd" /dev/null \| grep -c $'\x1b\['` → 0 (Linux). **Rust**: clap/anstream handle NO_COLOR, CLICOLOR(_FORCE), and TTY [S8]. **Node**: commander `useColor()` [S17], `tty.getColorDepth` [S16], and `util.styleText` unstyled when piped (E12). **Go**: no stdlib color, so check `term.IsTerminal(int(os.Stdout.Fd()))` and `os.Getenv("NO_COLOR") != ""` yourself (E7). Linux (P2): all three reference CLIs color on a real PTY (`script -qec`), print none with `NO_COLOR=1` or when piped. Codex sets `NO_COLOR=1` and `TERM=dumb` for every command, including PTY runs (P3). | from py OUT-04; S24, S8, S16, S17, E12, E13, P1, P2, P3 |
| OUT-03 | Spinners, progress bars, and `\r` redraws appear only when stderr is a TTY. | MUST | B C A | `tool longcmd 2>err </dev/null; grep -c $'\r' err` → 0 | from py OUT-05; S44 |
| OUT-04 | A pager starts only when stdout is a TTY, and `PAGER` is honored. Codex sets `PAGER=cat` and Claude Code sets none (E13), so the TTY check is what protects you. | MUST | B C A | `timeout 10 tool cmd \| cat; echo "${PIPESTATUS[0]}"` is not 124 | from py OUT-06; S30, S35 |
| OUT-05 | Output is never lost at exit. No hard exit while buffered or asynchronous output is pending: exit through one place after flushing. | MUST | B C A | `tool list --limit 100000 \| wc -l` equals the expected count. **Go**: `os.Exit` skips defers, so a deferred `Flush` is lost (E5, S3). Use `func main() { os.Exit(run()) }` with all defers inside `run`. **Rust**: `process::exit` runs no destructors [S10], so return `ExitCode` from `main`. **Node**: `process.exit()` can truncate piped stdout on POSIX [S15], so set `process.exitCode`. **Python**: `sys.exit` flushes. Observed on Linux (P2): 10 MB written then `process.exit(0)` delivered **64,000 bytes** (one pipe buffer) to a slow reader; with `process.exitCode` all 10,000,000 arrived. | S3, S10, S15, E5, E12, P1, P2 |
| OUT-06 | A closed pipe (`tool \| head -1`) ends the program quietly: no panic, no stack trace, exit 0 (or 141 by signal on Unix). | SHOULD | B C A | `(tool big-list 2>err) \| head -1; test ! -s err`. Output must exceed the 64 KB pipe buffer. **Rust**: `println!` panics (E9, S9, S11), so use `writeln!` and map `BrokenPipe` to success. **Node**: unhandled EPIPE crash (E12), so add a `process.stdout.on('error')` handler. **Go**: dies by SIGPIPE on Unix [S4], but on Windows writes fail with an error that is **not** `syscall.EPIPE` (E6). Check write errors in long loops. **Python**: py OUT-08. Linux (P2): Go dies quietly by SIGPIPE (exit 141), so even the cobra template passes there while it fails on Windows; check both OSes (TST-07). Rust `println!` (exit 101) and Node without the EPIPE handler (exit 1, stack) fail on Linux too. | from py OUT-08; S4, S9, S11, S15, E6, E9, E12, P1, P2 |
| OUT-07 | Human output is line-oriented, one record per line, no box borders. If the default is a table, a `--plain`/TSV or `--json` form exists. | SHOULD | B C A | `tool list \| wc -l` equals the record count | from py OUT-07; py:S16 |
| OUT-08 | Output is deterministic: stable order, no timestamps or random IDs unless asked for, ISO 8601 times instead of "3 days ago". | SHOULD | B C A | Run twice and `diff` | from py OUT-09 |
| OUT-09 | State-changing commands print a brief confirmation, and `-q`/`--quiet` silences it. | SHOULD | B C A | Run a mutation, then the same with `-q` | from py OUT-10; S44 |
| OUT-10 | Ctrl-C/SIGTERM stops quickly with bounded cleanup and exit 130 (SIGINT), without a stack trace. | SHOULD | B C A | `timeout --preserve-status -s INT 2 tool longcmd 2>e; echo $?` → 130 and no trace. Go exits on SIGINT by default [S4]; add `signal.NotifyContext` only if cleanup is needed. Linux (P2): Go, Rust, and Node reference CLIs all exit 130 with empty stderr on SIGINT and no handler. Send the signal with `timeout -s INT`, not to a `&` background job: those ignore SIGINT in a non-interactive shell. | from py OUT-11; S4, P2 |

### 2.3 Exit codes (EXIT)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|
| EXIT-01 | Success exits 0 and every failure exits non-zero, including partial failures. Never exit 0 after printing an error. | MUST | B C A | Trigger a known failure and check `echo $?` ≠ 0. **urfave/cli v3**: a plain error from an Action reaches `main` as an error; if `main` ignores it, the exit "falls through to 0" [S2]. **cobra**: `Execute()` only returns the error, so `main` must exit non-zero (S1, E1). | from py OUT-02; S2, S1 |
| EXIT-02 | Exit codes follow one documented, stable table: 0 success, 1 runtime failure, 2 usage error, 3–125 only for failure classes a caller branches on (not found, conflict, transient, confirmation required). Never reuse 2 for runtime failures, and avoid 124, 126, 127, and 128+N except 130. Codes stay ≤ 125 for portability [S3]. | MUST | B C A | Read the README or `--help` table. Grep the code for every exit value and compare. **oclif**: `this.error()` defaults to exit **2** [S19], so pass `{exit: 1}` for runtime failures. Agents don't always see these codes: Codex on Windows runs each command through `pwsh -Command`, which reports any failed native command as 1, so exits 2, 3, 124, 127, and 130 all reached the model as 1 (P3). Only `; exit $LASTEXITCODE` passed the real code through. The stderr message must say what happened without the code (ERR-02); the codes are for scripts that run the binary directly. | from py OUT-03 and the patterns.md exit-code table; S3, S19, py:S16, P3 |
| EXIT-03 | Exit 1 is reserved for real failures. Agent harnesses count your tool's exit 1 as a failure: Claude Code accepts benign exit 1 only from a fixed list (`grep`, `rg`, `find`, `diff`, `test`, `git diff`, `git grep`) and returns a failure as a 10,000-char head-and-tail excerpt with no file path [S25]. "No matches" or "differences found" exit 0 with the result in the output. | MUST | B C A | Run the "no results" and "differences" paths and check that each exits 0 | from py AGT-11, OUT-03; S25 |
| EXIT-04 | Exit codes are set in one place: `main` maps the error from `run()` to a code. Go `func main() { os.Exit(run()) }`, Rust `fn main() -> ExitCode`, Node `process.exitCode = code`. No scattered `os.Exit`/`process.exit` in library code. | SHOULD | B C A | `rg -n "os\.Exit\(\|process::exit\(\|process\.exit\(" ` lists only the entry point | S3, S10, S15, P1 |
| EXIT-05 | Each documented exit code is covered by a test (TST-02). | SHOULD | B C A | Map the exit-code table to test cases | from py TST-04 |

| AGT-10 | Destructive operations without a TTY require explicit confirmation (`--yes`/`--confirm`). | AGT-13 | Lookup commands accept several identifiers in one call (`tool show A B C --json` returns one array), so agents don't pay startup, config, and auth cost once per item. | SHOULD | B C A | `tool show id1 id2 --json \| jq length` → 2 | from py AGT-14 |
| AGT-14 | Inputs are flags and positionals. Structured input is only an extra path from a file or stdin (`--input spec.json`, `-`), never only an inline JSON string, because shell quoting breaks it (worst on PowerShell). | SHOULD | B C A | Every required value has a flag | from py AGT-15; S34 |

### 2.7 Discoverability and help (DISC)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|
| DISC-01 | `--help` alone is enough to use each command: one-line purpose, required vs optional arguments, defaults, enum values, 1–3 real examples, a mention of `--json`, and the exit codes (root or a `help exit-codes` topic). | SHOULD | B C A | Give an agent only `tool --help` and see whether it completes a typical task (TST-05). **clap**: put examples in `after_help`, or check that `-h` (short) still shows them [S7]. | from py AGT-12, CLI-04; S27, py:S19, py:S16 ("lead with examples") |
