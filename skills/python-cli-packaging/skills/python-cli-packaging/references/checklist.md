# Python CLI checklist

99 items with stable IDs. Sources: [sources.md](sources.md).

**Shared rows:** 44 items state the language-neutral agent contract that the `agent-friendly-cli` skill owns. Their Source cell starts with `afc:<ID>`, and their rule text and severity are copied from that skill by `scripts/sync_shared.py` in the skills repo, so edit the rule there, not here. Citations in that text use the other skill's sources (`afc:S30`). The Verify cell, with its **Python:** notes, belongs to this skill. Commands in tables escape `|` as `\|`; copy runnable commands from [checks.md](checks.md) instead.

Modes: **B** build, **C** convert, **A** audit. Every item applies in audit mode unless the mode column says otherwise. The only items without A are the convert-only LAY-08, DOC-05, and DIST-03.

**`<code>` in Verify commands** means every package directory and top-level module the wheel ships, not tests: `src/` in a src layout, or for example `huawei_config.py tools/` in a flat one. Grepping `src/` in a flat repo matches nothing, so the check passes without checking anything.

**Windows:** run behavioural checks with UTF-8 mode forced off: `PYTHONUTF8=0 env -u PYTHONIOENCODING tool ...`. Dev machines often set these variables, and Python 3.15+ turns UTF-8 mode on by default, so a plain run hides the OUT-12 crash that users on 3.14 and older hit.

### 2.3 CLI interface and help (CLI)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|
| CLI-01 | Arguments go through a real parser (argparse, click, or typer). No hand-parsing of `sys.argv`. | MUST | B C A | `rg -n "sys\.argv\[\d+\]\|len\(sys\.argv\)\|in sys\.argv" <code>` finds nothing. The default `sys.argv[1:] if argv is None else argv` is fine. | S16, S1 |
| CLI-02 | `-h` and `--help` work on the root and every subcommand, print to **stdout**, exit 0, and win over other arguments. | MUST | B C A | `for s in $(subcommands); do tool $s --help >/dev/null \|\| echo FAIL $s; done` | afc:CLI-02 |
| CLI-03 | Running with no arguments shows the subcommand list or usage and performs no action. Default for multi-command tools: help on stdout, exit 0 (a bare call is a discovery step, and harnesses show non-zero as failure). Usage on stderr with exit 2 is acceptable if documented. | SHOULD | B C A | `tool </dev/null; echo $?` prints usage and does nothing | afc:CLI-05 |
| CLI-04 | Every command's help has a one-line description and at least one working example. | SHOULD | B C A | Read `tool <sub> --help` and look for an "Examples" or epilog section | S16, S17, S18, S30 |
| CLI-05 | `tool --version` prints the version to stdout and exits 0. | MUST | B C A | `tool --version; echo $?` | afc:CLI-06 |
| CLI-06 | Every flag has a long form with a conventional name (`--json`, `--quiet`, `--verbose`, `--output`, `--dry-run`, `--yes`/`--force`, `--no-input`, `--no-color`, `--limit`), and names are unambiguous (`--user-id`, not `--user`). Single-letter flags exist only for common options. `--` ends options, and `-` means stdin or stdout where a file is expected. | SHOULD | B C A | Read the flag list in `--help` | afc:CLI-08 |
| CLI-07 | Flags are preferred over positionals. At most one positional kind. One command grammar throughout (for example noun-verb: `tool deploy list`, `tool config list`). | SHOULD | B C A | Read the help. Two different positional types is a smell. | afc:CLI-09 |
| CLI-08 | A usage error (unknown flag, unknown subcommand, missing or extra argument, bad value or choice) exits **2**, prints its message on stderr, and leaves stdout empty. | MUST | B C A | `tool --bogus >o 2>e; echo $?` prints 2, `test ! -s o`, `test -s e` | afc:CLI-03, S52 |

| CLI-11 | Where a file is expected, `-` means stdin or stdout. | NICE | B C A | `echo data \| tool cmd -` | S16, S33 |

### 2.4 Output and exit codes (OUT)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|
| OUT-01 | Data goes to stdout. Logs, progress, warnings, errors, and prompts go to stderr. | MUST | B C A | `tool cmd 2>/dev/null` shows only data and `tool cmd >/dev/null` shows only diagnostics. `rg -n "print\(" <code>` and check each one that is not data. | afc:OUT-01 |
| OUT-02 | Success exits 0 and every failure exits non-zero, including partial failures. Never exit 0 after printing an error. | MUST | B C A | Trigger a known failure (missing file, bad credentials) and check that `echo $?` is not 0. `rg -n "except.*:\s*$" -A3 <code>` to find swallowed errors. | afc:EXIT-01 |
| OUT-03 | Exit codes follow one documented, stable table: 0 success, 1 runtime failure, 2 usage error, 3–125 only for failure classes a caller branches on (not found, conflict, transient, confirmation required). Never reuse 2 for runtime failures, and avoid 124, 126, 127, and 128+N except 130. Codes stay ≤ 125 for portability [afc:S3]. | MUST | B C A | **Python:** document the table in the README or the `--help` epilog (patterns.md, Exit codes). A `diff`-style non-failure exit 1 must be documented in `--help`; prefer exit 0 with the result in the output. `grep -i "exit code" README*`, then `rg -n "return .*\b2\b\|exit\(2\)" <code>` and confirm each hit is a usage error | afc:EXIT-02 |
| OUT-04 | No ANSI escapes when stdout is not a TTY, when `NO_COLOR` is non-empty, when `TERM=dumb`, or with `--no-color`. Decide with an isatty check plus `NO_COLOR`, never with `TERM` alone: Claude Code runs commands with `TERM=xterm-256color` and no TTY (afc:E13). | MUST | B C A | `tool cmd \| grep -c $'\x1b\['` prints 0. `NO_COLOR=1 script -qc "tool cmd" /dev/null \| grep -c $'\x1b\['` prints 0 (Linux). | afc:OUT-02 |
| OUT-05 | Spinners, progress bars, and `\r` redraws appear only when stderr is a TTY. | MUST | B C A | `tool longcmd 2>err.txt </dev/null; grep -c $'\r' err.txt` prints 0 | afc:OUT-03 |
| OUT-06 | A pager starts only when stdout is a TTY, and `PAGER` is honored. Codex sets `PAGER=cat` and Claude Code sets none (afc:E13), so the TTY check is what protects you. | MUST | B C A | `timeout 10 tool cmd \| cat; echo "${PIPESTATUS[0]}"` is not 124 (bash; plain `$?` would report `cat`) | afc:OUT-04 |
| OUT-07 | Human output is line-oriented, one record per line, no box borders. If the default is a table, a `--plain`/TSV or `--json` form exists. | SHOULD | B C A | `tool list \| wc -l` equals the number of records | afc:OUT-07 |
| OUT-08 | A closed pipe (`tool \| head -1`) ends the program quietly: no panic, no stack trace, exit 0 (or 141 by signal on Unix). | SHOULD | B C A | **Python:** handle `BrokenPipeError` as the Python docs describe, plus `OSError` EINVAL on Windows, and flush stdout inside the `try` in `main` (patterns.md). `cli_contract.py --pipe-run "<args printing over 64 KB>"` on each OS. Linux: `(tool list 2>err.txt) \| head -1; grep -c Traceback err.txt` prints 0. The output must be larger than the pipe buffer (about 64 KB), or EPIPE never fires and the check passes falsely. | afc:OUT-06, S5, S63 |
| OUT-09 | Output is deterministic: stable order, no timestamps or random IDs unless asked for, ISO 8601 times instead of "3 days ago". | SHOULD | B C A | Run the same command twice and `diff` the outputs | afc:OUT-08 |
| OUT-10 | State-changing commands print a brief confirmation, and `-q`/`--quiet` silences it. | SHOULD | B C A | Run a mutating command and look for a one-line confirmation, then check that `-q` silences it | afc:OUT-09 |
| OUT-11 | Ctrl-C/SIGTERM stops quickly with bounded cleanup and exit 130 (SIGINT), without a stack trace. | SHOULD | B C A | **Python:** catch `KeyboardInterrupt` in `main` and return 130; uncaught, it also exits 130 on Linux but prints a traceback (S63). `timeout --preserve-status -s INT 2 tool longcmd 2>e; echo $?` prints 130 and `grep -c Traceback e` prints 0 (without `--preserve-status`, GNU timeout reports 124) | afc:OUT-10, S63 |
| OUT-12 | Output with non-ASCII text survives being piped or redirected on Windows (no `UnicodeEncodeError` from cp1252): call `sys.stdout.reconfigure(encoding="utf-8")` in the entry point. Every `open()` of a text file passes `encoding=`. Keep the `reconfigure` call while `requires-python` allows anything below 3.15. | SHOULD | B C A | On Windows: `PYTHONUTF8=0 env -u PYTHONIOENCODING tool cmd-with-unicode > out.txt; echo $?` prints 0. Not `env -u PYTHONUTF8` alone: on 3.15+ UTF-8 mode is the default, so that passes even when the code is broken. `python -X warn_default_encoding -m pytest` shows no `EncodingWarning`. | Local test (Windows 10, Python 3.14.3): piped `print('→')` fails with `'charmap' codec` unless `PYTHONUTF8=1`. PEP 597 (`EncodingWarning`), PEP 686 and the 3.15 "What's new" (UTF-8 mode on by default; `PYTHONUTF8=0` or `-X utf8=0` turns it off). |

### 2.5 Agent-friendliness (AGT)

| ID | Item | Sev | Modes | Verify | Source |
|---|---|---|---|---|---|

Structured input is only an extra path from a file or stdin (`--input spec.json`, `-`), never only an inline JSON string, because shell quoting breaks it (worst on PowerShell). | SHOULD | B C A | Read `--help`: every required value has a flag. `rg -n "json.loads\(args\." <code>` and check each has a flag equivalent | afc:AGT-14 |
