## Local tests (L), run 2026-11-18 on Windows with uv 0.13.9 (via `uvx uv@latest`; the installed uv is 0.11.3), git-cliff 2.14.2, towncrier 26.9.0, commitizen 4.19.3, python-semantic-release 10.7.0, zizmor 1.32.0, hatchling + hatch-vcs (latest from PyPI), in throwaway repos under `%TEMP%`. Nothing was pushed or published.
- L1: `uv init --lib` project (uv_build 0.13.9) with `dynamic = ["version"]`: `uv build` fails with `missing field 'version'`. uv_build needs a static version.
- L2: `uv version` and `uv version --bump patch` on a hatch-vcs project: `error: We cannot get or set dynamic project versions in: pyproject.toml`.
- L3: `uv version --bump` chain: `0.1.0 -> (minor+alpha) 0.2.0a1 -> (alpha) 0.2.0a2 -> (rc) 0.2.0rc1 -> (stable) 0.2.0 -> (patch+dev) 0.2.1.dev1 -> (post) 0.2.1.post1`. The last step skips the 0.2.1 final release. `--bump stable` from `0.2.1.post1` refuses: "didn't increase the version". `uv version 1.0.0-RC1` normalizes to `1.0.0rc1`, and `uv version v2.0` to `2.0`.
- L4: hatch-vcs with tag `v0.1.0`: on the tag it builds `0.1.0`. One commit later it builds `0.1.1.dev1+gc74f68e7c`. With a dirty tree it builds `0.1.1.dev1+gc74f68e7c.d20261118`. A `git clone --depth 1` (no tags) builds `0.1.dev1+gc74f68e7c` with no error or warning.
- L5: An sdist built by hatch-vcs rebuilds to the same version without `.git` (version read from `PKG-INFO`). `SETUPTOOLS_SCM_PRETEND_VERSION=9.9.9` overrides the version. `SETUPTOOLS_SCM_PRETEND_VERSION_FOR_SCMT=9.9.8` had **no effect** through hatch-vcs.
- L6: Rebuilding after `touch`ing files gives byte-identical sdist and wheel for uv_build, and for hatchling + hatch-vcs (with or without `SOURCE_DATE_EPOCH`), on the same machine. Build output inside the repo gets swept into the next hatchling sdist (untracked, not ignored files are included), so always build into a clean `dist/`.
- L7: git-cliff 2.14.2 with no `cliff.toml`: after tag `v0.1.0`, `feat`/`fix` commits give `--bumped-version` `v0.2.0`. Adding one `feat!:` commit gives `v1.0.0`. So the default config leaves 0.x on a breaking change.
- P1: the `release.yml` in patterns.md: its gate steps, extracted with `yq` and run on a scratch repo, passed on a correct `v1.2.0rc1` tag (tag on main, version == tag, changelog entry, one sdist, no local version) and rejected a mismatched tag and a `+g123` filename; the notes step extracted exactly the version's changelog section and added `--prerelease --latest=false`. `zizmor --persona pedantic` 1.32.0 and `actionlint` report nothing. The workflow has not run on GitHub.
